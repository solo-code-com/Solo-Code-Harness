## 2. Mười vấn đề đã sửa

### F1 — Version deploy sinh ra sai (Cao)

`tools/deploy.py` đọc `fallback-version` trong `pyproject.toml` để đóng dấu
`.harness.lock`, nhưng giá trị vẫn là `4.1.0` trong khi `agent.yaml` đã lên `4.2.0`.
`tools/garden.py` so sánh `agent.yaml` version với `.harness.lock` version, nên mọi
project vừa deploy xong bị báo drift ngay.

Bằng chứng trước khi sửa — sinh lock vào thư mục tạm bằng chính hàm của deploy:

```
[NEW] .harness.lock — generated (v4.1.0, 54 shared paths)
version = "4.1.0"
```

Sửa: bump `fallback-version` lên `4.2.0`. Sau khi sửa, cùng lệnh in `v4.2.0`.

### F2 — `.harness.lock` gốc ở format cũ (Cao)

Lock gốc chỉ có hai section (`[harness]`, `[boundaries]`), liệt kê `.github`,
`.vscode`, `tools` như harness nguyên khối, và vẫn mô tả engine `jcode` đã retired.
Template chuẩn sinh ra thêm `[shared_files]` và tách `shared_dirs`. `AGENTS.md` dặn
agent đọc `[shared_files]` nhưng mục đó không có. Không test nào kiểm tra lock gốc
(chỉ test lock sinh trong `tmp_path`).

Sửa: viết lại lock — 8 harness dir, 3 shared dir, 69 shared path, 18 file gốc.

### F3 — Template lock lệch khỏi data model deploy (Cao)

`HARNESS_LOCK_TEMPLATE` trong `tools/deploy.py` là chuỗi tĩnh, không ràng buộc gì với
`ROOT_FILES`, `EXCLUSIVE_HARNESS_DIRS`, `SHARED_DIRS`. Hệ quả:

- `.opencode` (cả một engine dir) thiếu khỏi `dirs`.
- `opencode.json`, `eslint.config.js`, `.env.template` thiếu khỏi `files`.

Mọi lock deploy ra đều nói với model rằng ba file đó là code dự án được phép sửa.

Sửa: thêm `.opencode` và ba file. Thêm 4 test ràng buộc template với data model và
lock gốc với `fallback-version` (trong `tools/test_deploy.py`).
